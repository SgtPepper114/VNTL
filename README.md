# VNTL · 日语游戏翻译

本仓库 fork 自 [itsNokts/VNTL](https://github.com/itsNokts/VNTL)，在上游文字提取与翻译浮窗的基础上，扩展了持续观察、本地日文 OCR、简体中文预译、假名注音、游戏上下文及手柄背键操作。

VNTL 是面向 Windows 的日语游戏翻译工具。选择游戏或模拟器窗口后，程序持续读取画面、记录剧情并准备中文译文。默认使用手动显示模式，按翻译键查看当前台词；切换到自动显示模式后，新台词译好即显示。两种模式共享后台观察和剧情记忆，也可通过文字钩子、剪贴板获取台词。

当前版本在 [`codex/continuous-observation`](https://github.com/SgtPepper114/VNTL/tree/codex/continuous-observation) 分支开发。具体操作见 [使用说明](使用说明.md)。

本地识字准确度、逐字字幕回放和实际接口耗时见 [持续观察验证记录](docs/observation-validation-20261113.md)。

## 主要功能

| 功能 | 当前实现 |
| --- | --- |
| 持续观察 | 选择游戏窗口后在后台识字，等待逐字字幕稳定，记录新台词和场景 |
| 本地日文 OCR | 使用 MeikiOCR 0.3.5 在 CPU 上识字，模型准备完成后支持离线推理 |
| 手动／自动显示 | 手动模式按键显示预译缓存，自动模式在新译文就绪时显示 |
| 文字提取 | 支持 PC 视觉小说的 GDI 文字钩子，以及剪贴板自动翻译 |
| 日中双语浮窗 | 显示日文与简体中文，支持拖动、缩放、字体与配色调整 |
| 汉字假名注音 | 在日文汉字上方显示平假名，可在外观设置中切换 |
| 游戏上下文 | 配置作品名称、篇章、角色称呼、术语和翻译风格，随模型请求一同发送 |
| 剧情记忆 | 原文读取后进入记忆，译文和场景随后补充，达到 token 阈值后后台整理摘要 |
| 视觉辅助 | 自动标定游戏画面，场景模型异步补充信息，疑难 OCR 调用视觉模型校验 |
| 历史与重译 | 查看本次翻译记录、剧情摘要及近期记录，按当前设置重新翻译台词 |
| 手柄操作 | 支持 USB 连接的 Nintendo Switch 2 Pro 手柄，通过 GR 或 GL 背键触发翻译 |
| 模型配置 | 分别配置翻译、截图 / OCR、摘要角色的供应商与模型 |

## 安装与启动

持续观察的运行环境：Windows 10 2004 及以上版本或 Windows 11、Python 3.11 及以上版本、[uv](https://docs.astral.sh/uv/)。翻译与视觉模型可使用 API 服务或本机 Ollama 服务。

```powershell
git clone --branch codex/continuous-observation https://github.com/SgtPepper114/VNTL.git
cd VNTL
uv sync --locked
uv run python main.py
```

`uv sync --locked` 会依据锁定的依赖版本创建项目虚拟环境。首次启用本地识字时，程序下载约 **46 MB** 的三个固定版本 MeikiOCR 模型文件，校验固定的 SHA-256 后保存到 `~/.config/vntl/models/meiki/`。后续识字通过本地模型在 CPU 上运行。

首次启动后：

1. 点击浮窗 **⚙ → 接口与模型**，填写 API Key，并为翻译、截图 / OCR、摘要选择模型。截图 / OCR 角色使用支持图片输入的模型。
2. 在 **游戏** 页填写当前游戏名称与补充说明，保存设置。
3. 启动游戏，点击 **选择游戏窗口**，按窗口标题、程序名或 PID 选择目标。窗口列表将应用排在前面，后台进程放在可展开的分组中。
4. 保持游戏窗口位于前台且画面可见。默认先由截图模型标定游戏画面，后续本地裁切并观察，台词稳定后记录原文并预译；底部状态栏显示进度。
5. 按 **GR**、**Ctrl+Alt+T** 或点击 **识屏翻译**，显示当前台词的缓存译文。缓存准备期间，显示请求会等待当前台词就绪。

## 翻译模式与识屏设置

顶栏的 **手动显示／自动显示** 按钮切换中文的显示时机，**观察开启／观察暂停** 按钮控制后台观察。也可在 **⚙ → 识屏** 中保存设置。

| 识屏设置 | 默认值 | 作用 |
| --- | --- | --- |
| 翻译显示模式 | 手动显示 | 按翻译键显示中文；自动模式在新译文就绪时显示 |
| 连续观察游戏画面 | 开启 | 选择游戏窗口后进行本地识字、预译和场景观察 |
| 自动识别游戏画面 | 开启 | 首次选定窗口和窗口尺寸变化时由截图模型标定，后续使用本地裁切 |
| 字幕稳定等待 | 600 毫秒 | 主体文字或逐行文字框保持稳定的等待时间；范围 200–2000 毫秒 |
| 画面检查间隔 | 200 毫秒 | 控制本地画面的检查频率；范围 100–1000 毫秒 |
| 字幕区域起点 | 0% | 手动补充识字区域的上边界，相对于游戏画面高度；范围 0–90% |
| 字幕区域下边界 | 100% | 手动补充识字区域的下边界，相对于游戏画面高度；范围 10–100%，大于起点 |
| 后台观察场景 | 开启 | 通过视觉模型补充人物、地点和画面变化 |
| 场景变化阈值 | 5% | 数值越小，越容易将画面变化交给视觉模型；字幕区域参与屏蔽 |
| 场景观察最短间隔 | 10 秒 | 控制场景模型的请求间隔；范围 3–120 秒 |

自动识别通过截图模型区分游戏画面与宿主窗口的菜单、状态栏。首次选定窗口及窗口尺寸变化时进行标定，后续帧按标定结果在本地裁切。标定失败时先使用完整窗口继续本地观察，后台按 5、15、30、60 秒间隔重试，后续间隔保持 60 秒。按翻译键可提前重试；成功后自动采用新边界并更新状态。网络代理配置变化后，后续模型请求自动更新连接。

字幕上下边界相对于识别后的游戏画面，默认 **0%–100%** 覆盖全画面。可根据字幕布局手动调整上下边界，进一步限定识字区域。关闭“自动识别游戏画面”后，完整窗口作为边界参照。场景观察使用完整游戏画面。

稳定判断允许少量 OCR 抖动；主体文字或逐行文字框稳定后接收字幕，每轮候选等待最长 **4 秒**，随后提交当前候选。此策略借鉴 [GameSentenceMiner](https://github.com/bpwhelan/GameSentenceMiner) 的稳定判断思路，由 VNTL 独立实现。

同一页字幕继续追加并稳定后，程序更新这一页的原文与译文。场景描述与预译并行进行，完成的场景信息进入记忆，供后续翻译参考。识字结果受画面清晰度、字体和区域选择影响，可通过双语浮窗对照原画面核对。

持续采集使用 Windows 窗口捕获排除机制，浮窗在观察期间保持稳定显示。切换到其他应用、最小化游戏或打开设置期间，后台观察暂停；返回游戏后自动继续。

**观察暂停** 时，翻译键切换为按需视觉识屏：短暂隐藏 VNTL 浮窗、截取当前画面，再交给视觉模型识字并翻译。

## 常用操作

| 入口 | 操作 |
| --- | --- |
| **GR** / **Ctrl+Alt+T** / **识屏翻译** | 持续观察时显示当前台词的预译缓存；暂停观察时执行视觉识屏 |
| **手动显示／自动显示** | 切换中文译文的显示时机 |
| **观察开启／观察暂停** | 开始或暂停后台观察与预译 |
| **Ctrl+Alt+H** | 显示或隐藏浮窗 |
| **↻** | 使用当前设置与上下文，重新翻译最近识别的日文 |
| **≡** | 查看本次运行的翻译记录 |
| **Σ** | 查看剧情摘要及近期记录 |
| **⚙** | 打开设置 |
| **✕** | 保存当前状态并退出 VNTL |
| 浮窗右键菜单 | 保存、载入、清空剧情记忆，手动整理摘要，连接文字钩子 |

浮窗支持拖动和调整大小，长段字幕可滚动查看。在 **设置 → 外观 → 背景不透明度** 调整字幕底色：0% 为背景完全透明，100% 为背景完全不透明，文字和按钮保持自身颜色。顶部控制栏保持可见，可用于拖动浮窗和打开设置。背景颜色选择器中的透明度与滑块同步；外观变化即时预览，保存后保留，取消后恢复。后台观察和预译状态显示在底部状态栏，字幕区域保留当前内容。

PC 视觉小说可在右键菜单选择 **连接文字钩子（PC 视觉小说）…**，再选择所需文本流。配合外部文本提取工具时，可在 **设置 → 上下文** 启用 **自动翻译剪贴板文字**。钩子的逐字等待默认 150 毫秒，本地 OCR 的字幕稳定等待默认 600 毫秒，分别在上下文页和识屏页配置。

## 汉字上方假名注音

在 **设置 → 外观 → 日文汉字上方显示假名注音** 中切换，初始状态为开启。

注音直接排在对应汉字或词语的上方，例如「学校」上方显示「がっこう」；「感じ」中的「感」上方显示「かん」，后面的「じ」保持原样。中文译文显示在日文下方。

读音由本地 SudachiPy 与 SudachiDict-core 词典生成。切换设置时，字幕、翻译历史和剧情记忆视图会即时预览；点击保存后应用到后续启动。复制、模型请求和记忆文件均使用日文原文；角色名和特殊读音可结合游戏画面对照。

## 游戏上下文与剧情记忆

**设置 → 游戏** 提供 **当前游戏名称** 和 **补充说明**。可填写作品与篇章、已确认的人物关系、角色称呼、固定术语和对白风格，例如：

> 游戏内角色名保留日文写法；现实人物使用通用中文译名。对白采用自然、简洁的中文。

这些信息会随识屏、翻译、场景描述及摘要请求发送。补充说明中的翻译偏好优先于默认规则和历史译文；保存后从下一次请求生效，也可点击 **↻** 更新当前台词。

稳定读取的原文即进入剧情记忆，中文译文随后补充。场景观察也可独立成条，按时间顺序记录。**设置 → 上下文** 中可调整：

| 设置 | 默认值 | 作用 |
| --- | --- | --- |
| 开始整理记忆的阈值 | 10,000 tokens | 控制自动整理摘要的启动条件 |
| 摘要目标长度 | 5,000 tokens | 控制摘要篇幅 |
| 保留最近完整记录 | 30 条 | 保留近期台词与场景记录的完整内容 |

上下文达到 token 阈值且存在可整理的较早记录时，立即启动后台摘要。原文、译文和场景更新均可触发检查，手动模式也持续积累记忆。摘要完成后更新剧情记忆及 **Σ** 视图。当前台词的显示缓存独立保存，整理历史后仍可按键查看。

记忆更新后自动保存到 `contexts\自动保存.json`，启动时优先恢复此文件。迁移旧版资料时，自动读取 `contexts\黄昏症候群_自动保存.json`，后续更新写入通用路径，旧文件保留。切换作品、存档或路线时，通过右键菜单管理对应记忆，并更新当前游戏资料。

## 手柄背键

**设置 → 手柄** 可配置 USB 连接的 Nintendo Switch 2 Pro 手柄。默认由右背键 **GR** 触发识屏翻译，也可选择左背键 **GL**。

VNTL 读取手柄的原始 HID 数据，将一次背键按下转换为一次翻译请求。设置页提供启用开关、按键选择与连接状态。手柄重新连接后，监听会自动恢复。

## 模型与本地数据

支持 DeepSeek、Google、Anthropic、OpenAI 和 Ollama。翻译、截图 / OCR、摘要三个角色可分别选择供应商与模型；截图 / OCR 角色负责游戏画面标定、场景描述和疑难识字校验。**提示词** 页分别编辑翻译、场景描述和摘要的系统提示词。

API Key 可在设置中填写，也可通过 `DEEPSEEK_API_KEY`、`GOOGLE_API_KEY`（或 `GEMINI_API_KEY`）、`ANTHROPIC_API_KEY`、`OPENAI_API_KEY` 环境变量提供。Ollama 服务地址可在设置中配置。后台预译、游戏画面标定、视觉校验、场景描述与摘要请求按所选模型服务的规则计费。

模型连接跟随系统及环境变量的代理设置，支持直连。Windows 默认使用系统证书库验证 HTTPS，兼容系统已经信任的企业或安全软件证书。`SSL_CERT_FILE` / `SSL_CERT_DIR` 可指定证书来源；`NO_PROXY` 可指定直连目标。代理或证书环境配置变化后，后续请求自动刷新连接。

本地数据保存在当前 Windows 用户的 `%USERPROFILE%\.config\vntl\` 目录：

| 路径 | 内容 |
| --- | --- |
| `config.json` | 模型连接、游戏资料、外观、识屏与上下文配置 |
| `models\meiki\` | 本地 OCR 模型缓存 |
| `contexts\自动保存.json` | 自动保存的剧情记忆 |
| `contexts\` | 剧情记忆文件；手动导出时可选择保存位置 |
| `vntl.log` | 程序运行日志 |
| `translate.log`、`describe.log`、`summarize.log` | 对应角色的模型调用记录 |

## 开发与打包

离线测试与格式检查：

```powershell
uv sync --locked
uv run python -m unittest discover -s tests -v
git diff --check
```

生成 Windows 程序目录：

```powershell
.\build.bat
```

构建脚本使用 PyInstaller，将程序、Qt 组件、文字钩子、OCR 运行库及注音词典打包到 `dist\vntl\`。运行其中的 `vntl.exe`，分发时保留整个目录结构。OCR 模型使用上述用户目录缓存。

本仓库的 `main` 分支与上游版本保持对应，持续观察功能在 `codex/continuous-observation` 分支开发。`origin` 对应个人 fork，`upstream` 对应 `itsNokts/VNTL`；提交使用 `feat:`、`fix:`、`docs:` 等 Conventional Commits 类型。

感谢 [itsNokts/VNTL](https://github.com/itsNokts/VNTL) 提供文字钩子、翻译流程与浮窗基础，以及 [MeikiOCR](https://github.com/rtr46/meikiocr)、[SudachiPy](https://github.com/WorksApplications/SudachiPy)、[SudachiDict](https://github.com/WorksApplications/SudachiDict) 和 [SDL](https://github.com/libsdl-org/SDL) 提供的识字、词典工具与手柄协议参考。
