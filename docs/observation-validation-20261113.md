# 持续观察验证记录 · 2026-11-13

本次使用《黄昏症候群 探索篇》开头录像验证本地识字与逐字字幕处理。游戏区域已裁掉左侧直播信息；识字准确度采用统一的底部字幕截图，视觉基准来自 DeepSeek 识图并经人工对照画面核验。

## 本地识字

环境：Windows 10 19045、Ryzen 7 8845H、Python 3.13.5、MeikiOCR 0.3.5、ONNX Runtime 1.31.1，CPU 推理使用 4 个线程。三份模型使用固定版本及 SHA-256 校验。

| 指标 | 原始 MeikiOCR | 当前封装 |
| --- | ---: | ---: |
| 固定截图数 | 20 | 20 |
| 含字截图完全正确 | 13 / 18 | 16 / 18 |
| 字符错误率 | 5 / 411 = 1.22% | 2 / 411 = 0.49% |
| 空白截图误报 | 0 / 2 | 0 / 2 |
| 热启动识字耗时 | 约 61 毫秒 | 约 60 毫秒 |

字符错误率计算前使用 NFKC、移除空白并保留标点。当前封装在行尾字框内检查推进图标的像素轮廓，依据倒三角收尖形状或纸页折角形状、尺寸和置信度进行过滤。真实字体「口／ロ／一／ー／し／円／回」另有保留测试。

## 逐字显示回放

对五段已人工标注“最后一个字出现”的字幕，按 200 毫秒间隔采样，直接运行生产 `MeikiReader` 与 `TextStabilizer`，稳定等待为 600 毫秒。

| 指标 | 图标过滤前 | 图标过滤后 |
| --- | ---: | ---: |
| 最终完整文字触发 | 4 / 5 | 5 / 5 |
| 完整之后额外触发 | 3 次 | 0 次 |
| 完整文字出现至触发 | 2.59–3.80 秒，另有一段漏发 | 0.79–0.88 秒 |

修复后的六次事件包含一次整页完成前的完整问句，其后同页继续追加。这个行为对应“完整句子稳定后先译，后续追加更新同一条字幕”的交互选择。

回放延迟按录像时间轴计算，源视频一帧约 41.7 毫秒；识字的运行耗时和云端翻译耗时单独测量。

## 实际模型调用

使用五张完整游戏画面，运行生产观察服务、MeikiOCR 和已配置的 `deepseek-flash`。每张图启动本地观察、预译及并行场景描述；识字区域起点为 60%。每张图对应一次翻译与一次场景请求，这五张图均走正常本地识字路径。

持续观察一列包含本地识字、稳定等待和实际翻译调用；原视觉路径从完整截图直接发请求。两列都使用当前游戏资料及空白实验剧情记忆。首轮模型导入、校验和预热另外耗时约 1.43 秒。

手动模式可以在台词稳定后预先完成这些工作。缓存就绪时，翻译键直接调用字幕显示；本实验测得缓存回调中位耗时 0.017 毫秒，仅表示内存取值及回调分发。玩家感受到的按键延迟还包含手柄轮询、输入队列和 Qt 绘制。

`tools/benchmark_observation.py` 可对完整游戏图片重测实际 API 路径，读取设置中的供应商配置，实验日志写入指定输出目录，剧情记忆使用独立的内存实例：

```powershell
uv run python tools/benchmark_observation.py --crop-top 60 --vision-baseline --output validation/benchmark frame1.png frame2.png
```

## 交互与持久化验证

263 项自动化测试通过，覆盖手动静默预译、自动单次显示、同页追加、清屏后重复句、OCR 抖动恢复、模型失败后重试、目标窗口与上下文切换、旧结果丢弃、场景请求限频、视觉判空、摘要期间显示缓存、旧存档迁移和设置保存／取消。

窗口捕获另用两个有明确颜色的测试窗口实测：前景窗口保持可见，经 Windows 捕获排除设置后，截图得到其背后的测试窗口颜色。后台循环因此可以保持翻译浮窗稳定显示。

本机 Qt 运行包附带的 MSVC DLL 版本为 14.26，系统版本为 14.51。Qt 先加载旧 DLL 时，ONNX Runtime 曾出现原生崩溃。启动引导先加载受信任路径下的兼容运行库；构建子进程使用相同顺序，分发目录包含对应运行库。源码与打包程序均通过 Qt 创建后、后台线程真实 OCR 的离线检查。开发者可使用 `vntl.exe --check-ocr IMAGE OUTPUT.json` 检查分发环境。

构建进程的 PATH 仅保留 Python 与 Windows 目录，Qt 使用系统 ICU，避免其他桌面工具的同名 DLL 混入分发包。最终分发程序已启动并核对模式按钮及观察状态。

## 结果适用范围

准确度来自固定的 20 张截图；逐字判稳来自五段开头字幕；接口耗时来自五次配对试验，受网络、上下文长度及服务负载影响。开头样本支持当前方案的可用性判断。后续游玩可继续覆盖其他字体、竖排文本、菜单、人物演出与字幕区域，并据此调整判稳参数和图标识别规则。

字幕区域选择影响可见文字范围；60% 适合本次底部对白，菜单和顶部字幕可使用 0%。新场景描述与正常预译并行，场景结果进入后续翻译上下文；疑难识字会等待视觉校验，因此耗时可高于普通本地识字路径。
